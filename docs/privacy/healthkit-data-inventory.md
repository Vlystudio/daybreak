# HealthKit data-minimization inventory

V1 asks for read access only after the user opens Settings → Connections → Apple Health and continues past the pre-permission disclosure. No type is requested at cold launch or signup. Daily aggregates, sleep intervals, and workout summaries are sent to Daybreak&apos;s Supabase backend; no raw all-history sample stream is uploaded. Each stored observation retains source, timestamps, unit, aggregation/provenance, import time, and confidence metadata. Health context reaches OpenAI only after separate basic and health AI consent.

Explicitly not requested: blood glucose, blood pressure, body temperature, clinical records, reproductive health, medications, audio, and all write/share types. The native bridge can map some broader units internally, but the JS allowlist is authoritative and tests reject those identifiers. Apple does not disclose whether every read type was individually denied; Daybreak reports only availability, user action, returned data, and errors, never a false per-type denial claim.
