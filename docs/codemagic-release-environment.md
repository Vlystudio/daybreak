# Codemagic iOS release environment checklist

The `ios-healthkit` workflow builds a native Capacitor shell that loads `https://daybreak-one.vercel.app`. Codemagic signs and uploads the shell; it does **not** build or host the production Next.js application. Web runtime configuration therefore belongs in Vercel, while Apple signing material belongs in Codemagic.

## Repository-controlled release values

Review these in the exact release commit before starting a build:

| Value                 | Expected source/value                                                                             | Check                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Workflow              | `ios-healthkit` in `codemagic.yaml`                                                               | Select it explicitly for a manual candidate; automatic publishing runs only for pushes to `main`.                                  |
| Bundle ID             | `app.daybreak.mobile`                                                                             | Must match Capacitor, Xcode, App ID, profile, and App Store Connect record.                                                        |
| App version           | `APP_VERSION` in `codemagic.yaml`                                                                 | Set to the approved marketing version before the release build.                                                                    |
| Build number          | Latest App Store Connect build plus one                                                           | The workflow queries the configured App Store record and applies the result with `agvtool`; do not run candidates concurrently.    |
| Workspace/scheme      | `ios/App/App.xcworkspace`, `App`                                                                  | Generated by Capacitor/CocoaPods and validated before archive.                                                                     |
| Production URL/domain | `https://daybreak-one.vercel.app` / `daybreak-one.vercel.app`                                     | Must match `capacitor.config.ts`, `ios-release-validate.sh`, `HEALTH_DOMAIN`, and `WKAppBoundDomains`. HTTPS only.                 |
| Build images          | Node 22, Xcode 26.0, default CocoaPods                                                            | Confirm the selected Codemagic image is still available before release; a YAML parse does not prove the remote image or toolchain. |
| Native privacy files  | Info.plist purpose strings, `PrivacyInfo.xcprivacy`, HealthKit entitlements, icons, splash assets | `npm run ios:validate` checks the generated project; archive validation additionally checks the signed IPA entitlement.            |

Codemagic's official [Xcode 26.0.x machine specification](https://docs.codemagic.io/specs-macos/xcode-26-0/) lists Xcode `26.0.1` on the Mac mini M2 image and says `xcode: 26.0` selects it. Therefore the declared Xcode selector and `mac_mini_m2` combination are supported as of July 13, 2026. A successful candidate build must still record the actual `xcodebuild -version`; documentation availability does not prove that this repository archives successfully.

The build-number step follows Codemagic's official [native iOS build versioning procedure](https://docs.codemagic.io/yaml-quick-start/building-a-native-ios-app/#build-versioning): it obtains the latest build for `APP_STORE_APPLE_ID`, adds one, persists the candidate through `CM_ENV`, and validates the same value in the signed IPA. This requires a valid App Store Connect integration and serial candidate builds; concurrent candidates could select the same number.

## Codemagic UI configuration

In the Codemagic application, verify without copying secret values into tickets or logs. The environment group must be restricted to trusted release branches and workflows.

| Name                                   | Purpose                                        | Secret? | Configured at / expected format                                                  | Needed for        | Safe verification                                                                                                |
| -------------------------------------- | ---------------------------------------------- | ------- | -------------------------------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `APPLE_TEAM_ID`                        | Match signing assets to Apple developer team   | No      | Codemagic `appstore` group; 10-character team ID                                 | Signing           | Presence check; compare to decoded profile `TeamIdentifier` without printing the value.                          |
| `BUNDLE_ID`                            | Native application identifier                  | No      | Repository YAML; `app.daybreak.mobile`                                           | Build/sign/upload | Compare to Capacitor, Xcode, decoded profile application identifier, and App Store record.                       |
| `APP_VERSION`                          | Marketing version                              | No      | Repository YAML; approved `major.minor.patch`                                    | Build/upload      | Inspect YAML and generated `CFBundleShortVersionString`.                                                         |
| `APP_STORE_APPLE_ID`                   | Locate the existing App Store record           | No      | Codemagic `appstore` group; numeric Apple ID                                     | Build numbering   | Presence/numeric check; compare the record bundle ID in App Store Connect without logging credentials.           |
| `CANDIDATE_BUILD_NUMBER`               | Monotonic build version                        | No      | Generated as latest App Store Connect build plus one; persisted through `CM_ENV` | Build/upload      | Compare candidate `CFBundleVersion` and archive evidence; never run two candidate workflows concurrently.        |
| `CM_CERTIFICATE`                       | Apple Distribution certificate and private key | Yes     | Codemagic `appstore` group; base64 `.p12`                                        | Signing           | Decode to a temporary file and run `openssl pkcs12 -noout`; do not print certificate contents.                   |
| `CM_CERTIFICATE_PASSWORD`              | Unlock `.p12`                                  | Yes     | Codemagic `appstore` group                                                       | Signing           | Use only through `-passin env:` and keychain import; never echo it.                                              |
| `CM_PROVISIONING_PROFILE`              | App Store profile with HealthKit               | Yes     | Codemagic `appstore` group; base64 `.mobileprovision`                            | Signing           | Decode temporarily; compare team/bundle, check HealthKit entitlement and expiration without dumping the profile. |
| `Daybreak ASC Key` integration         | Authenticate App Store Connect upload          | Yes     | Codemagic integration; issuer ID, key ID, private `.p8`; name must match YAML    | Upload            | Confirm integration status/permissions in UI and perform candidate upload; never print `.p8`.                    |
| `PRODUCTION_URL` (repository constant) | Remote web application loaded by shell         | No      | `capacitor.config.ts`; `https://daybreak-one.vercel.app`                         | Runtime           | Compare config, release validation script, HTTPS response, and `WKAppBoundDomains`.                              |

Repository access and the webhook must also be active for `Vlystudio/daybreak`. Certificate and profile must be distribution credentials, not development or ad-hoc assets, and must not be expired or revoked.

The workflow validates presence, certificate password, profile team, bundle identifier, and HealthKit entitlement without echoing secret values. It deliberately fails before archive on any mismatch.

## Triggering the candidate branch

Automatic push builds are intentionally limited to `main`; this prevents every review-branch push from publishing to TestFlight. To build the current candidate before merge:

1. Open **Codemagic → Applications → Daybreak**.
2. Choose **Start new build**.
3. Select branch `codex/app-store-launch-readiness` and workflow `ios-healthkit`.
4. Confirm the displayed commit equals the reviewed/pushed branch tip.
5. Confirm environment group `appstore` and integration `Daybreak ASC Key` are available to the workflow.
6. Start the build. This workflow is configured to publish a successful IPA to TestFlight; do not start it against an unintended App Store Connect account.

No Codemagic API token or authenticated trigger surface is committed to the repository. If using the Codemagic API instead of the UI, create the build against the same application, branch, workflow, and exact commit, and keep the token entirely in the operator's secret manager.

Before pressing Start, verify:

- the branch tip and release-evidence commit match;
- `APP_VERSION` is the approved marketing version;
- `APP_STORE_APPLE_ID` selects the intended record and no other candidate workflow is running;
- the App Store record, App ID, profile, and YAML all use `app.daybreak.mobile`;
- the profile is App Store distribution, unexpired, same-team, and HealthKit-capable;
- the production Vercel deployment and required runtime variables are healthy; and
- no database or device blocker is being represented as cleared merely because a build is starting.

Retain the build URL/ID and the logs for asset determinism, project validation, signing preflight, archive validation, and publishing. Expected artifacts are the `.ipa`, `.xcarchive`, dSYM bundle, and sanitized `build/release-evidence/ios-archive.json`. The JSON deliberately does not claim an Xcode privacy report, TestFlight processing/install, or device behavior.

## Production web runtime (Vercel)

Because the installed app opens the deployed site, verify the Production environment of the Vercel project independently. Required values from `src/env.ts` are:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `NEXT_PUBLIC_APP_URL=https://daybreak-one.vercel.app`
- `SUPABASE_SERVICE_ROLE_KEY`
- `TOKEN_ENCRYPTION_KEY` (and, if rotating, `TOKEN_ENCRYPTION_KEYS` plus `TOKEN_ENCRYPTION_ACTIVE_KEY`)
- `CRON_SECRET` (and temporary `CRON_SECRET_PREVIOUS` only during rotation)
- `ADMIN_ACTION_SECRET` (dedicated to high-impact support/admin mutations; never reuse the cron secret)

| Runtime variable(s)                                                  | Purpose                                             | Secret?                      | Where / format                                                           | Safe verification                                                                                   |
| -------------------------------------------------------------------- | --------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`          | Browser Supabase endpoint/session access            | Public                       | Vercel Production; HTTPS URL and publishable anon key                    | Check presence and project host in Vercel UI; run authenticated staging smoke without printing key. |
| `NEXT_PUBLIC_APP_URL`                                                | OAuth/email redirects and canonical runtime         | Public                       | Vercel Production; exact reviewed HTTPS origin                           | Request legal/auth routes and compare redirects.                                                    |
| `SUPABASE_SERVICE_ROLE_KEY`                                          | Server administrative operations including deletion | Yes                          | Vercel Production; service-role JWT                                      | Presence check and synthetic staging deletion; never expose to client/build logs.                   |
| `TOKEN_ENCRYPTION_*`                                                 | Encrypt stored provider tokens                      | Yes                          | Vercel Production; base64 32-byte active key plus optional rotation JSON | Run environment validation and an OAuth round trip; never print decoded keys.                       |
| `CRON_SECRET*`                                                       | Authenticate scheduled endpoints                    | Yes                          | Vercel Production; high-entropy string, at least 16 characters           | Presence/length check and authorized cron response; do not put secret in evidence.                  |
| `ADMIN_ACTION_SECRET`                                                | Authenticate high-impact admin actions              | Yes                          | Vercel Production; distinct high-entropy value, at least 32 characters   | Presence/length check and denied wrong-secret test; do not put secret in evidence.                  |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Web push subscription and delivery                  | Mixed; private key is secret | Vercel Production; matching VAPID keypair and `mailto:`/HTTPS subject    | Synthetic-device subscribe/send/unsubscribe check; never print private key.                         |

Feature-specific values must either be valid in Production or the feature must be intentionally unavailable and accurately represented to reviewers:

- AI: `OPENAI_API_KEY`; food recognition may additionally use `LOGMEAL_API_KEY`.
- OAuth: `OURA_CLIENT_ID/SECRET`, `FITBIT_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`.
- Notifications: `RESEND_API_KEY`, `EMAIL_FROM`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`.
- Optional data: `WEATHER_API_KEY`, `SPOONACULAR_API_KEY`, `GROCERYTRACKER_URL`, `GROCERYTRACKER_ANON_KEY`.
- Observability: `NEXT_PUBLIC_SENTRY_DSN` or an intentional empty value. Confirm health data and secrets are redacted under the provider retention policy.
- V1 social, household, Nest, and subscription features are source-locked off in
  `src/lib/features.ts`; release environments cannot enable them accidentally.

`NEXT_PUBLIC_*` values are compiled into the deployed web build. Changing them requires a new Vercel production deployment; rebuilding only the iOS shell does not update them.

## Safe operator checks

Run checks in the Codemagic script or an approved local macOS shell. These commands report only success or failure and metadata that is already expected; never enable `set -x`:

```bash
set -euo pipefail
: "${APPLE_TEAM_ID:?missing}"
: "${CM_CERTIFICATE:?missing}"
: "${CM_CERTIFICATE_PASSWORD:?missing}"
: "${CM_PROVISIONING_PROFILE:?missing}"
: "${APP_STORE_APPLE_ID:?missing}"
[[ "$APP_STORE_APPLE_ID" =~ ^[0-9]+$ ]]

echo "$CM_CERTIFICATE" | base64 --decode >/tmp/daybreak-check.p12
openssl pkcs12 -in /tmp/daybreak-check.p12 \
  -passin env:CM_CERTIFICATE_PASSWORD -noout

echo "$CM_PROVISIONING_PROFILE" | base64 --decode >/tmp/daybreak-check.mobileprovision
security cms -D -i /tmp/daybreak-check.mobileprovision >/tmp/daybreak-check.plist
test "$(/usr/libexec/PlistBuddy -c 'Print :TeamIdentifier:0' /tmp/daybreak-check.plist)" = "$APPLE_TEAM_ID"
test "$(/usr/libexec/PlistBuddy -c 'Print :Entitlements:application-identifier' /tmp/daybreak-check.plist)" = "$APPLE_TEAM_ID.app.daybreak.mobile"
/usr/libexec/PlistBuddy -c 'Print :Entitlements:com.apple.developer.healthkit' /tmp/daybreak-check.plist >/dev/null
rm -f /tmp/daybreak-check.p12 /tmp/daybreak-check.mobileprovision /tmp/daybreak-check.plist
```

Also record, without secrets:

```bash
xcodebuild -version
node --version
grep -n 'BUNDLE_ID\|APP_VERSION\|xcode:' codemagic.yaml
npm run ios:validate
```

## Candidate build evidence and stop conditions

For the candidate tied to a commit hash, retain the Codemagic build URL and ID, workflow name, Xcode version, marketing and build number, certificate/profile expiration confirmation, generated-project validation log, archive validation log, IPA artifact checksum, App Store Connect upload result, and TestFlight build number. Fill in `docs/ios-release-evidence-template.md` without copying secrets or raw profiles into the document.

Do not release if any required variable or integration is missing; the team, bundle, or HealthKit profile differs; the production URL is not the reviewed HTTPS deployment; the Vercel production environment is invalid; the signed IPA lacks HealthKit; App Store Connect rejects the upload; or a physical-device camera, HealthKit, or deletion gate remains unverified.
